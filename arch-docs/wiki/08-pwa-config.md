# PWA & Deployment Configuration

## Progressive Web App

The site is a PWA, meaning it can be installed on mobile devices and works offline.

### PWA Setup

**Library:** `@ducanh2912/next-pwa` (wraps Workbox)

**Configuration** in `next.config.mjs`:
```javascript
const withPWA = withPWAInit({
  cacheOnFrontEndNav: true,          // Cache pages on client-side navigation
  aggressiveFrontEndNavCaching: true, // Pre-cache aggressively
  reloadOnOnline: true,              // Reload when connectivity restores
  dest: "public",                     // Service worker output directory
  fallbacks: {
    document: "/offline"              // Show /offline when no cache hit
  }
});
```

### Manifest

**File:** `public/manifest.json`

```json
{
  "name": "Prompt Engineers AI - Dallas Plano AI Community",
  "short_name": "Prompt Engineers AI",
  "theme_color": "#000000",
  "background_color": "#000000",
  "display": "standalone",
  "start_url": "/",
  "icons": [
    { "src": "/icons-192.png", "sizes": "192x192" },
    { "src": "/icons-256.png", "sizes": "256x256" },
    { "src": "/icons-512.png", "sizes": "512x512" }
  ]

```

### Service Worker

Generated by Workbox at build time into `public/sw.js`. Handles:
- Caching of navigation requests
- Offline fallback to `/offline` page
- Cache management and cleanup

### Offline Page

`src/app/offline/page.tsx` - Simple page displayed when user is offline and the requested page isn't cached. Shows a message encouraging reconnection.

## Deployment Notes

- **Inferred platform:** Vercel (Next.js default, `.vercel` patterns in `.gitignore`)
- **Serverless functions:** Each API route deploys as a separate serverless function
- **MongoDB connection:** Must account for serverless cold starts (connection pooling configured with appropriate timeouts)
- **Environment variables:** Must be set in Vercel project settings
- **Build output:** Static pages + serverless functions + service worker
